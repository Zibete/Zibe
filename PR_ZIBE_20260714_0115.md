# ✨ feat(ui): modernizar navegación, Descubrir y permisos

Base: `main` (`73bbfb36ddf5531603bd3be178d0d87ad7ecf298`)

Rama: `feature/ui-motion-discover-permissions`

## ✨ Qué se cambió

### Permisos y onboarding

- Unifica la educación de ubicación y notificaciones con el copy acordado y solicitudes secuenciales.
- Mantiene ubicación como requisito y notificaciones como opt-in no bloqueante en Android 13+.
- Agrega el modo notification-only para cuentas existentes que nunca recibieron el prompt.
- Persiste `wasRequested`, evita relanzamientos automáticos y restaura requests en curso sin duplicarlos.
- Mueve los launchers al borde Compose/Activity y elimina el requester singleton asociado a una Activity.
- Separa la recuperación explícita en Ajustes, con rationale contextual o apertura de la configuración específica según el estado real.
- Representa por separado runtime permission, estado global de notificaciones y channel de mensajes.

### Navegación final y Cuenta

- Elimina por completo el drawer, su hamburger, listeners, layouts, menú y recursos exclusivos.
- Ordena la navegación raíz como `Descubrir`–`Chats`–`Salas`–`Favoritos`, con `Chats` como start destination.
- Agrega el avatar de cuenta en la toolbar y un bottom sheet con `Editar perfil`, `Ajustes` y `Cerrar sesión`.
- Conserva badges, estado seleccionado, navegación de Salas/Favoritos y apertura de DM desde intents.
- Corrige la navegación raíz para usar destination IDs y preservar el back stack de NavComponent.

### Descubrir

- Migra la experiencia de personas desde RecyclerView/XML a Compose dentro de `UsersFragment`.
- Agrega búsqueda, filtro online, rango de edad, filtros activos, pull-to-refresh, loading, empty, error y retry.
- Mantiene perfil, favorito, estados reales y distancia sin lecturas Firebase desde composables.
- Consulta la conversación DM en el repositorio y muestra el aviso de primer contacto antes de abrir un chat nuevo.
- Usa keys estables, procesamiento de directorio fuera de Main y libera observers de presencia al salir de composición.
- Encola navegación/snackbars en `Channel` para no perder resultados async durante cambios de lifecycle.

### Sistema de movimiento

- Centraliza duraciones, easing, springs, presión, háptica semántica y reduced motion en `core:designsystem`.
- Aplica feedback medido a botones, tarjetas, chips, avatar, sheet y navegación, sin animar listas completas.
- Conserva la identidad oscura, rosa/violeta y los componentes visuales existentes de ZIBE.

## 🧭 Por qué

- Una instalación nueva podía llegar a Main en Android 13+ sin solicitar `POST_NOTIFICATIONS`.
- El drawer duplicaba navegación y no ofrecía una entrada clara a la cuenta.
- Descubrir dependía de una implementación View/XML costosa de evolucionar y con estados dispersos.
- Faltaba una base reusable y accesible para movimiento y feedback de interacción.

## 🔒 Contratos preservados

- Sin cambios en Functions, Rules, payloads FCM, paths RTDB ni semántica backend.
- Se preservan `MSG_DELIVERED (1)`, `MSG_RECEIVED (2)`, `MSG_SEEN (3)`, monotonicidad, fan-out atómico, server timestamps y unread.
- `messaging.send()` no se interpreta como receipt; sólo Android receptor confirma `MSG_RECEIVED`.
- Salas conserva el backend y la navegación legacy de Groups.
- No se actualizaron AGP, Gradle, Kotlin, KSP, Compose, Firebase, SDK levels ni dependencias de producción.

## ⚠️ Riesgos y pendientes

- La suite automatizada cubre la integración de launchers, pero no reemplaza el comportamiento visual de prompts OEM ni una reinstalación física autenticada.
- FCM real requiere credenciales, backend activo y dos usuarios/dispositivos; queda pendiente y mantiene el PR en draft.
- Permanecen warnings baseline de APIs deprecadas fuera del alcance; no se agregaron suppressions ni se modificó el toolchain.

## 🚫 Fuera de alcance

- Backend de Salas públicas, reacciones, nuevos payloads FCM o cambios de Groups.
- Navigation 3, reescritura completa de `MainActivity`, rediseño de Auth, tema claro o dynamic color.
- Cambios o deploy de Functions, Rules, Hosting, releases o tags.

## 🚫 Sin deploy

No se desplegó Firebase ni ningún servicio remoto. No se mergeó, publicó release ni creó tag.
